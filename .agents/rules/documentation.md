# ドキュメントルール (Documentation Rules)

本リポジトリにおけるドキュメント配置および記述方針は以下のルールを厳守してください。

---

## 1. README.md の責務
- **対象読者**: VS Code 拡張機能の利用者（エンドユーザー）
- **記載内容**:
  - 拡張機能の概要・目的
  - 対応フォーマット（JSON / YAML 等）
  - エディタの仕様（パス表示、型認識、インライン編集、項目追加・削除、検索フィルター）
  - 書式保持仕様
  - 起動方法・使い方
  - 開発者ドキュメントへのリンク（末尾）
- **禁止事項**:
  - 内部アーキテクチャ詳細、ソースディレクトリ構成、テストコマンド、ビルドスクリプト等の開発者向け技術詳細を `README.md` に直接記述しないこと。

---

## 2. docs/ ディレクトリの責務
- **対象読者**: 拡張機能のメンテナー・開発者・コントリビューター
- **配置構造**:
  - `docs/developer-guide.md`: 開発環境のセットアップ、ビルド・テスト手順、アーキテクチャ概要、新フォーマット拡張手順
  - `docs/adr/`: アーキテクチャ意思決定記録（ADR）。大きな設計判断やライブラリ選定時は必ずここに記録を追加すること。
  - その他、開発者向けの専門資料・詳細仕様書

---

## 3. 意思決定記録 (ADR) の運用ルール
- アーキテクチャ構造の変更、新しいコアライブラリの導入、データ変換戦略の変更を行う際は、必ず `docs/adr/` 配下に連番（例: `006-xxx.md`）で ADR を作成し、背景・代替案・決定理由・結果を記録すること。

---

## 4. ソースコード・JSDoc・テストコードの言語原則
- **ドキュメント出力対象の言語統一**:
  TypeDoc（API仕様書）やテスト仕様書（`docs/test-specifications.md`）として出力されるすべての JSDoc/docstring、およびソースコード内の解説コメントは、**日本語**で記述すること。
- **クラス・関数・引数・戻り値の説明**:
  クラス、インターフェース、メソッド、プロパティ、パラメータ（`@param`）、戻り値（`@returns`）の説明文は日本語で明記する。
- **テストコードの仕様記述**:
  各テスト関数には、必ず日本語で `【観点】` および `【テスト内容】` を明記した JSDoc を付与すること。
- **絵文字の禁止**:
  docstring、コメント、テスト名、ドキュメント全般において絵文字は一切使用しないこと。

---

## 5. 自動生成ドキュメントのGit管理ルール
- **Git管理対象**:
  `docs/api/`（TypeDoc生成のAPI仕様書群）および `docs/test-specifications.md`（テスト仕様書）は、GitHub上およびエディタ内での直接閲覧を可能にするため、Markdown形式のまま**Git管理（コミット対象）**とします。
- **コード変更時の同時コミット義務**:
  ソースコードまたはテストコードを変更した際は、コミット前に必ず `npm run doc` を実行してドキュメントを同期更新し、同一のコミット／PRに含めること。
- **非Markdownファイルの除外**:
  HTMLや中間キャッシュファイル等の非Markdownアセットはリポジトリにコミットしないこと。
