# ADR 006: ソースコードおよびテスト仕様の動的ドキュメント化戦略

## ステータス
承認済み (Accepted)

## コンテキスト
本プロジェクトは、クリーンアーキテクチャ（ADR 001）に基づいて構築されており、ドメイン層・ユースケース層・インフラ層の責務が厳密に分離されています。
また、各機能や型推論、リネーム、並び替え、削除などの重要な振る舞いは、Vitestによる単体テスト群によって検証されています。

しかし、以下の課題がありました:
1. **API仕様・型定義ドキュメントの保守コスト**: ソースコードの変更に合わせて手動でMarkdownドキュメントを更新するのは形骸化しやすく、コードとドキュメントの乖離が発生するリスクがある。
2. **テスト観点・テスト仕様の可視化**: 「何がどういう観点でテストされているか」という仕様（Living Documentation）をプロジェクト関係者が一目で把握・追跡できる仕組みが不足していた。

## 決定
ドキュメント形式の乱立を防ぎ、GitHubやエディタ上で直接一元管理・閲覧できるよう、**すべてのドキュメントをMarkdown（.md）形式に統一して自動生成**する方針を決定しました:

1. **ソースコード仕様（APIドキュメント）: TypeDoc + typedoc-plugin-markdown**
   - TypeScriptの型定義および JSDoc / TSDoc コメント（`/** ... */`）を直接解析。
   - すべてMarkdown形式として `docs/api/` 配下に自動出力。
   - HTML等の外部Webアセットを出力せず、リポジトリのGitバージョン管理・GitHubプレビューに完全適合させる。

2. **テスト仕様書（Living Documentation）の自動生成: `scripts/generate-test-docs.js`**
   - 各テストコード内の JSDoc コメント（`【観点】`、`【テスト内容】`）を自動抽出し、モジュール・スイート別の詳細一覧表（[`docs/test-specifications.md`](../test-specifications.md)）をMarkdownとして自動生成。
   - ソースコードを開かずに、どの機能に対してどのような観点で詳細テストが行われているかを俯瞰可能とする。

3. **Git管理（コミット対象）方針**:
   - `docs/api/` および `docs/test-specifications.md` はリポジトリの Git 管理対象（コミット対象）とし、コード変更と同一のコミット／PRで同期管理する。
   - GitHub 上やローカルエディタで、追加のビルド操作なしに即座に最新の仕様書を閲覧可能とする。

4. **npm スクリプトの整備**:
   - `npm run doc`: TypeDoc Markdown API仕様書とテスト仕様書（Markdown）を一括生成
   - `npm run doc:test`: テスト仕様書（`docs/test-specifications.md`）のみを高速生成
   - `npm run test:report`: Vitest HTML レポートの生成
   - `npm run test:ui`: Vitest インタラクティブUIの起動

## 結果
- **利点**:
  - **コードとの完全同期**: JSDocやテストコードを更新してコマンドを実行するだけで、常に最新のAPI仕様とテスト観点一覧が自動生成される。
  - **GitHub上での直接閲覧性**: Markdown形式でGit管理されるため、GitHubのリポジトリ画面やPR差分上で仕様書のリンクを辿ってそのまま閲覧・レビューが可能。
  - **可視性の向上**: テストの合否だけでなく、「どのような観点で何を検証しているか」がコードを開かずにMarkdown一覧表およびブラウザ上で明確に可視化される。
  - **ゼロ追加ランタイム負荷**: ビルド成果物（拡張機能本体）のファイルサイズやランタイムパフォーマンスには一切影響を与えない（すべて devDependencies）。
