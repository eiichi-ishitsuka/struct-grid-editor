# ADR 002: ネスト構造のフラット化戦略とパス表現

## ステータス
承認済み (Accepted)

## コンテキスト
JSON や YAML は任意の深さを持つツリー構造（ネストされたオブジェクトや配列）を持ちます。一方でスプレッドシート（グリッド）は2次元の行×列の表形式です。
任意のネスト構造をスプレッドシート形式で表示・編集可能にし、かつ元のネスト構造へ可逆的に復元する仕組みが必要でした。

検討したアプローチ:
1. **アプローチA (列展開方式)**:
   - ルート配列の各要素を1行とし、ネストしたプロパティ（例: `address.city`）をカラムヘッダーとして横に広げる。
   - 課題: ルートがオブジェクトの場合（配列ではない場合）に成立しない。また配列の中に配列がある場合などに列数が爆発する。
2. **アプローチB (パス-値 行展開方式 - 採用)**:
   - 全てのリーフ（末端の値ノード）を1行とし、`パス (Path)`, `型 (Type)`, `値 (Value)` を表示する。
   - パスは `user.address.city` や `servers[0].port` のようにドット記法および配列インデックス記法で一意に識別。
   - インデント（深さ `depth`）と階層コネクタ（`└─`）により視覚的にツリー構造を認識可能にする。

## 決定
**アプローチB（パス-値 行展開方式）** を採用しました。

### コアコンポーネント:
1. **`CellPath` Value Object**:
   - `segments: (string | number)[]` をイミュータブルに保持。
   - `fromString("users[0].address.city")` で双方向に安全にシリアライズ・デシリアライズ。
2. **`TreeFlattener` ドメインサービス**:
   - `flatten(root: TreeNode): FlatRow[]`
   - `unflatten(rows): any` により、フラット行から完全なネストツリーを再構築（可逆性を保証）。

## 結果
- **利点**:
  - ルートがオブジェクトでも配列でも、任意の深さのネストデータが均一なUIで表示・編集可能になった。
  - セル単位の更新が `CellPath` をキーとして高速かつ安全に行える。
  - パスや値に対する検索フィルターが容易に実装できた。
