# ADR 003: 元書式およびインデント・コメント保持の設計

## ステータス
承認済み (Accepted)

## コンテキスト
構造化データをエディタで開いて編集した際、元のファイルのインデント（2スペース、4スペース、タブ）や末尾改行が崩れてしまうと、Gitの差分が不必要に肥大化し、開発者体験を損ねます。
さらに、YAML ファイルではコメント（`# ...`）が重要な意味を持つため、コメントが消えてしまうエディタは実用上敬遠されます。

## 決定
1. **`DocumentFormat` Value Object**:
   - `fileType: 'json' | 'yaml'`
   - `indent: number | string`（2スペース、4スペース、タブ）
   - `hasTrailingNewline: boolean`
   - `metadata: Record<string, any>`（パーサー特有のASTや具象構文木情報を格納）
2. **`FormatPreserver` ドメインサービス**:
   - パース時にテキストを走査し、先頭のインデント幅や改行コード、末尾改行の有無を自動検知。
   - シリアライズ時に検知した書式設定を忠実に適用。
3. **YAML コメント保持**:
   - `yaml` パッケージの AST（`Document` オブジェクト）を `DocumentFormat.metadata` に保持し、ノード更新時に AST 構造を書き換えることでコメントとアンカーを保持。

## 結果
- 編集前後でインデント幅や改行スタイルが保持され、無駄な Git 差分が発生しない。
- YAML ファイルのコメントが消去されずに保存される。
